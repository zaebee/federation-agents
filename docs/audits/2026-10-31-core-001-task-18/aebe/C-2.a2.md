## 3. Positive evidence

Test: `C-2 cycle detection records CYCLE_DETECTED in an Assessment`
File: `tests/conformance/c.test.ts`

Graph:

```text
iv-a ──CONTINUATION──► iv-b
iv-b ──FORKED_FROM───► iv-a
```

The test imports `emitCycleAssessments` from `src/index.ts`, supplies a caller-owned ID callback, and asserts:

- both nodes are reported as one cyclic component (`[['iv-a', 'iv-b']]`);
- exactly two Assessments are registered — one per affected edge;
- `unverified_claims` is exactly `['CYCLE_DETECTED']` and `verified_claims` is empty;
- `parent_version_ids` has exactly one element (the edge parent);
- the graph JSON is unchanged;
- the registered representation is frozen;
- the system does not throw and declarations remain readable.

This is C-2.a2 evidence only. Asserting that dependent grants are not applied is `CASE-C-2.a3`, which belongs to CORE-003 and stays BLOCKED.

## 4. Shape and deterministic emission

Test: `emits one declaration-scoped assessment per affected edge, deterministically`
File: `tests/unit/cycle-assessment.test.ts`

Graph: `iv-a` continuations to `iv-b` and forks from `iv-d`; `iv-b` forks from `iv-a`; `iv-c` continuations to `iv-a`.

- Emitted records: `(['iv-a', 'CONTINUATION', ['iv-b']])`, `(['iv-b', 'FORKED_FROM', ['iv-a']])` — sorted by `(child, parent, relation)`. `assessments` follows that edge order; `registered` is the canonical representation sorted by `assessment_id`.
- `returns assessments in edge order even when assessment ids sort differently` pins the two orders apart (the caller supplies ids whose lexical order reverses the edge order).
- `iv-c → iv-a` and `iv-a → iv-d` are not affected edges and get no Assessment.
- Every record carries `verified_claims: []`, `unverified_claims: ['CYCLE_DETECTED']` and the caller's `evidence_refs`.

The adapter calls `registerCycleAssessments` once for the complete batch, including an empty batch. It stops before Core admission if the graph is not builder-issued or an ID callback throws/returns an invalid id. Callback side effects are outside Core atomicity and are not rolled back; caller persistence occurs only after `ok: true`.

## 5. Negative and boundary evidence

Tests in `tests/unit/cycle-assessment.test.ts`:

- `generic registration cannot admit a C-2 claim` — `registerAssessment` reports that the claim requires contextual admission and names `registerCycleAssessments`.
- `the C-1 contextual path rejects a C-2 claim` — an otherwise valid C-1 candidate that also records `CYCLE_DETECTED` is rejected; the claim stays on its own path.
- `the C-2 contextual path rejects a C-1 claim` — `PARENT_UNRESOLVED` is rejected on the cycle path.
- `rejects C-2 candidates that violate the contextual boundary` — one table over: `PARENT_UNRESOLVED` on the cycle path; two parent edges; an edge absent from the graph; an edge that exists but is not inside a cycle; a subject absent from the graph.
- `rejects a graph that was not produced by buildLineageGraph`.
- `rejects a duplicate assessment id across the batch`.
- `preserves existing assessments and returns a frozen combined representation`.

## 6. Self-loop limitation

Test: `skips a structural self-loop because the assessment contract forbids a self-parent`

A structural self-loop is detected by the graph as a one-node cyclic component. The adapter emits no Assessment for it because the Assessment contract rejects a subject that is its own parent (§5.2 also rejects self-parents for descriptors). Such an edge remains a graph-level cycle without an Assessment record; this sub-decision was not part of the approved `T18-DEC-16` resolution and is left open rather than silently relaxed.
