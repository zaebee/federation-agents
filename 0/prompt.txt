Главная находка: loop erasure описан некорректно
P1 — исправить до принятия пакета
В api-migration.md, §3.2.1, шаг 4 сказано:
Concatenate the two walks and loop-erase by keeping the first occurrence of each node in walk order.

Это не является корректным алгоритмом удаления циклов из пути.

Контрпример:
Исходный walk:
s → a → b → c → a → d → t

Если просто оставить первое вхождение каждой вершины:
s → a → b → c → d → t


Но ребра c → d в исходном графе может вообще не существовать. Полученная последовательность вершин не является путём.

Правильная операция — chronological loop erasure: поддерживать стек вершин и при повторном посещении вершины удалять из стека весь участок после её предыдущего вхождения. Например:
Исходный walk:
s → a → b → c → a → d → t

После корректного loop erasure:
s → a → d → t


Это не косметическая проблема. CycleWitness обязан содержать реальный простой путь, а не просто последовательность уникальных вершин. Иначе его нельзя независимо проверить, и утверждение о корректности D3 witness оказывается недостаточно обоснованным.

Что нужно исправить:
1. Заменить формулировку «keeping the first occurrence» точным алгоритмом chronological loop erasure.
2. Указать инвариант: после обработки каждого ребра стек представляет непрерывный directed walk без повторяющихся вершин.
3. Сохранить доказательство Lemma 4: после удаления циклов итоговый простой путь всё ещё содержит хотя бы одну вершину из C.
4. Добавить тест с повторным посещением промежуточной вершины, проверяющий непрерывность рёбер, отсутствие повторов и наличие циклической вершины.
Это касается как минимум api-migration.md и согласованности с описанием D3 в complexity-proof.md и oq4-complexity-adversarial-pass.md.
