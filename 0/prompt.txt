1. Новый P1 — Lemma 4: аргумент о сохранении циклической вершины всё ещё некорректен
В complexity-proof.md §3, oq4-complexity-adversarial-pass.md §2 и §4 осталось утверждение:
If c is erased, the erased closed subwalk has a first vertex y that survives in P, and that subwalk is a closed walk through y.

Это не следует из алгоритма. Если вершина y из первого удалённого подмаршрута впоследствии тоже удаляется, финальная вершина, которая переживёт loop-erasure, может вообще не принадлежать первоначальному замкнутому подмаршруту.

Здесь есть простой способ закрыть доказательство — не пытаться найти «первую выжившую вершину» внутри одного цикла, а проследить цепочку удалений.

Корректный аргумент:
1. Исходная прогулка содержит c ∈ C.
2. После обработки соответствующего участка c либо остаётся в стеке, либо удаляется при замыкании цикла. Во втором случае этот цикл начинается и заканчивается в некоторой вершине x, которая остаётся в стеке.
3. Замкнутая прогулка от x через c обратно в x означает, что x и c принадлежат одной SCC. Следовательно, x ∈ C.
4. Если x впоследствии удаляется, это происходит при замыкании следующего цикла с сохранённой вершиной y. Этот цикл содержит x, поэтому y находится в той же SCC и тоже принадлежит C.
5. Каждый такой переход происходит позже по исходной прогулке. Поскольку рёбер конечное число, цепочка заканчивается вершиной из C, которая остаётся в финальном стеке.
Значит, финальный loop-erased path обязательно содержит хотя бы одну вершину из C.

Это доказывает именно то, что нужно Lemma 4, и не требует, чтобы исходный pivot c пережил удаление.

Что попросить исправить: заменить аргумент Lemma 4 этим доказательством и синхронизировать формулировки в complexity-proof.md, oq4-complexity-adversarial-pass.md и api-migration.md. Последний документ уже правильно не предполагает, что исходный pivot обязательно сохранится.

2. P2 — заявленная сложность loop-erasure требует уточнения
В complexity-proof.md §7.1 алгоритм говорит:
if v already appears in stack at index i:
    pop every vertex after index i


Но не указано, как определяется, присутствует ли v в стеке и где именно. Если каждый раз линейно сканировать стек, сложность может стать O(V·E), а не заявленной O(V+E).

Исправление простое: поддерживать вместе со стеком индексную таблицу vertex → stack index.
- При добавлении вершины записывать её индекс.
- При удалении суффикса удалять индексы удалённых вершин.
- При повторном появлении вершины находить её позицию через таблицу.
Тогда алгоритм имеет ожидаемую O(V+E) сложность при hash map; если нужна строгая детерминированная оценка, следует указать структуру данных и её гарантии.

Это не опровергает алгоритм, но сейчас текст доказывает корректность стека, а не полностью обосновывает заявленную сложность.
