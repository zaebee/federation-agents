2. Оставшееся замечание

P2 — non-blocking
 Runtime-валидатор verifier пока не проверяет точную форму объекта.
Файл: src/core/credential.ts, isVerificationOutcome().

Сейчас проверяется discriminant и тип reason, но допускаются, например:
{ status: 'VERIFIED', reason: 'unexpected' }
{ status: 'VERIFIED', extra: true }


Хотя контракт SignatureVerificationOutcome разрешает reason только для CRYPTO_UNAVAILABLE и CRYPTO_UNSUPPORTED, а extra вообще не определён.

Также проверка не требует plain object: массив с добавленным свойством status теоретически тоже может пройти.

Рекомендация: сделать проверку строгой по вариантам union:
Status	Разрешённые поля
VERIFIED	status
INVALID	status
CRYPTO_UNAVAILABLE	status, optional reason
CRYPTO_UNSUPPORTED	status, optional reason

Отклонять неизвестные поля, массивы и объекты с неподходящей структурой.

Это не возвращает прежний fail-open для неизвестного discriminant, но завершает обещанную runtime-валидацию контракта.
