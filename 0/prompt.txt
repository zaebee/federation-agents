## 1.3 Develop independent semantic alternatives

**Option C — Explicit conflict predicate**

- same declared relation;
- same assessment scope;

You may propose another option if the specification or code requires it.

- normative support;
- what counts as a contradiction;
- whether claims are compared within one Assessment or across Assessments;
- whether `verified` versus `unverified` claims can conflict;
- whether two different assessors matter;
- how supersession affects conflict;
- whether timestamps or ordering matter;
- whether conflict is local to an edge, declaration, subject, or traversal;
- effect on `evaluateAssurance`;
- effect on `ApplicableAssessments`;
- effect on existing consumers;
- false-positive and false-negative risks;
- adversarial examples.

Do not invent a universal logical contradiction engine if the protocol only defines a small set of claim semantics.
